# 文体ガイド（開発記録）

`note-article/references/style.md` の厳守ルールを土台にする。**差分だけをここに書く。**
書いていないものは note 版と同じ。

## 立ち位置

書き手は、生成 AI を使ってアプリを作っている小学校の教員。
読み手も、たいてい同じことをしている人。**同業に向けた手紙**の距離で書く。

note の紹介記事は「使ってみませんか」だが、こちらは「こうやりました」。
勧めない。売り込まない。

---

## note 版から引き継ぐもの（変えない）

読み手が変わっても、**人が書いた文章に読めること**は同じ。

- **A1** 太字（`**`）を使わない
- **A2** 斜体、水平線を使わない
- **A4** 区切りの記号を使わない（`→` `⇒` `／` `▲` `▼` `▶` `◀` `※` `＞` `≫`）
- **A5** コロン `：` を使わない。ラベル出しをしない
- **A7** 絵文字は使わない
- **A8** かぎかっこは、アプリ名や画面に出る言葉を指すときだけ
- **A9** かっこ（）で補足しない。次の一文にする
- **A10** 数量は算用数字で書く。数えていない言葉（「一覧」「一度も」）と、
  和語の数詞（「一つ」「三つ目」）は漢数字のまま
- **B1** 前置きの宣言を書かない
- **B2** 安全クッションを書かない（「一般的に」「多くの場合」）
- **B3** 抽象語で押し切らない（「重要」「効率的」「革新的」「画期的」）
- **B5** 同義語の言い換え連打をしない
- **B6** 抽象的なまとめを繰り返さない
- **B7** 締めの定型句を書かない（「参考になれば幸いです」）
- **C1〜C5** リズム。文の長さを混ぜる。同じ文末を三つ続けない。一人称は「私」。です・ます調
- **D1** 教室での出来事を実体験として書かない
- **D3** 裏の取れていない数字を書かない
- **D6** 収益化の導線を入れない

## note 版から変えるもの

### 表を使ってよい（A2 の一部を解除）

note では表が表示されないので禁じていた。`/devlog/` は自前の HTML なので出る。
測った結果を並べるときは表のほうが読みやすい。

⚠️ 表は横に流れる。`/devlog/` 側の CSS が枠の中でスクロールさせるが、
**列は 4 つまで**にする。

### 数字と助数詞のあいだを空ける（A10 の一部を変える）

note の記事は「10秒」と詰める。開発記録は「31 本」「42 リポジトリ」と空ける。
測った数を並べる記事なので、空けたほうが数と単位の切れ目が目に入る。
漢数字と算用数字の使い分けそのものは A10 のまま。

### 箇条書きを使ってよい（A6 を解除）

行き止まりの列挙と「次に同じことをする人へ」は、箇条書きが素直。

⚠️ ただし**地の文の代わりにしない**。並べれば伝わるわけではないのは同じ。
考えの筋は文章で書き、結果だけを並べる。

### コード塊を使う（新規）

プロンプト、コマンド、エラーの出力、差分。すべて ``` で囲む。

⚠️ **囲みの中は文体のルールの外。** 原文のまま出す。整えない。
エラーメッセージのコロンや矢印を消してはいけない。

### 専門語を言い換えない（B8 を解除）

**これがいちばん大きな違い。** note 版は 14 語の言い換えを強制している。

```
デプロイ → 公開の設定
Service Worker → 裏で動く仕組み
リポジトリ → 公開しているファイルの置き場
```

**開発記録ではそのまま書く。** 読み手は作っている人で、言い換えると
かえって何の話か分からなくなる。`git`, `CI`, `WebP`, `CSP` も同じ。

ただし**略語を初出で開く**。`CSP` は 1 回目だけ
`Content-Security-Policy` と書く。読み手の守備範囲は人によって違う。

### 失敗の書き方（D2 の裏返し）

note 版の D2 は「効果を言い切らない」。開発記録では逆向きの注意が要る。

⚠️ **失敗をぼかさない。**

| 書かない | 書く |
|---|---|
| 想定と異なる結果になりました | 私の見落としでした |
| 調整が必要でした | 3 回作り直しました |
| 一部で問題が発生しました | 31 本のうち 9 本で止まりました |

⚠️ **自分を責める書き方もしない。** 事実を書けば足りる。
「お恥ずかしい話ですが」「猛省しています」は要らない。

## 題のつけかた

連載番号は付けない。`#◯` は note の記事のもの。

**何をしたか**ではなく、**何が起きたか**を題にする。

| 弱い | 強い |
|---|---|
| フッターにリンクを追加した | 31 本のうち 9 本には、置く場所が無かった |
| 画像を最適化した | 見積もりを 3 倍外した |
| CSS を修正した | 「すべて…」と切れた絞り込みは、壊れているのと同じ |

25〜40 字。

---

## 分量

全体 2,500〜7,000 字。節ごとの目安は `structure.md`。

⚠️ **短いほうに寄せる。** 開発記録は薄めると価値が落ちる。
書くことが 2,500 字ぶんしか無いなら、2,500 字で出す。
