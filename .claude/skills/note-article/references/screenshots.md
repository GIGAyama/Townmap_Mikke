# 画面を撮るときの落とし穴

ここに書いてあるのは、実際に踏んで誤った画像を作りかけたものだけ。
読まずに撮ると、たいてい同じところで転ぶ。

## まず土台を用意する

```bash
npm i --no-save playwright peer     # まとめて入れる。理由は 8 を見る
npm run build
node <skill>/scripts/serve.mjs dist 4180 /<リポジトリ名>/
```

`serve.mjs` の第3引数（ベースパス）を省かない。GitHub Pages で
`https://<user>.github.io/<repo>/` に置かれるアプリは、Service Worker や
manifest が `/<repo>/` という絶対パスを持っている。ルート直下で配ると、
そこだけ本番と挙動が変わってしまう。

シナリオを書いて撮る。

```bash
node <skill>/scripts/capture.mjs .tmp-shots/shots.mjs \
  --base http://127.0.0.1:4180/<repo>/ --out docs/note/images
```

## 0. 土台が肩代わりしてくれることを知っておく

`capture.mjs` は、失敗に気づかないまま進むことを防ぐために作ってある。
これを踏まえないと、同じ確認を手で書き足すはめになる。

- `click` は押せなかったら例外で止まる。そのとき「いま押せるもの」の一覧を出す。
  押せなくても構わないときだけ `{ optional: true }` を付ける
- 見えていないもの、`disabled` のもの、`aria-hidden` の下にあるものは
  最初から候補に入らない。前の画面の裏に残ったボタンを押してしまう事故が消える
- 部分一致で押したときと、候補が複数あったときは警告が出る
- `shot` は画面が止まるまで撮り直す。止まらなければ「演出の途中かもしれない」と言う
- `shot` は直前の1枚と見くらべて、同じ絵なら警告する
- 画面のエラーと読み込み失敗を集めて、最後にまとめて出す。`report.json` にも残る

だから、撮り終わったら必ず出力の最後を読む。警告が出ていたら、その画像を目で確かめる。

## 1. ふりがな（ruby）を落としてから文字を照合する

子ども向けアプリのボタンは `へやに<ruby>入<rt>はい</rt></ruby>る` のような形をしている。
`textContent` は「へやに入はいる」になるので、「へやに入る」で探しても当たらない。

`capture.mjs` は `click` も `has` / `waitFor` / `expect` / `text` も、
`<rt>` と `<rp>` を落としてから比べる。シナリオにはいつも**ルビを外した字**
（「へやに入る」）を書く。逆に、ふりがなのほう（「はいる」）では当たらない。

⚠️ 2026-08-30 まで、落としていたのは `click` だけだった。`has` の側は
`innerText` を見ていたので、**押せるのに待てない**という食い違いがあった。

```js
await p.click('へやに入る');            // 通る
await p.waitFor('へやに入る');          // 通らなかった（「へやに入はいる」なので）
```

`clickTo` は中で `waitFor` を呼ぶので、画面はちゃんと進んでいるのに
「画面が変わっていない可能性がある」と言って落ちる。原因が押した側にあると
読めてしまうため、遠回りしやすい。自分で `page.evaluate` を書くときも、
この処理を忘れない。

## 1-2. `onPointerDown` だけを見ているボタンがある

反応を速くしたいアプリ——とくに子どもが連打するキーパッド——は、
`click` ではなく `onPointerDown` で処理していることがある。

`capture.mjs` の `click()` は `pointerdown` → `mousedown` → `pointerup` →
`mouseup` → `click` の順に出すので、どちらの作りでも押せる。

⚠️ 2026-08-30 まで `el.click()` しか出していなかった。`onPointerDown` だけの
ボタンは**押せたことになるのに何も起きない**。`click` は成功を返し、
候補の一覧にも出ているので、シナリオを何度読み返しても分からない。
Qalc の計算画面がこれで、キーを押しても数字が入らなかった。

`pointerdown` を `preventDefault()` するアプリでは、そこで止める。
本物のブラウザもそうしていて、「`pointerdown` で処理して `click` は止める」
作りを二重に動かさないための分かれ道になっている。

自分で `page.evaluate` を書いて押すときは、同じ順で出すこと。

## 1-3. 候補に出ないもの、押せないもの

`click` が「押せなかった」と言ったとき、一覧に目当てのものが無ければ、
だいたい次のどちらか。

- **画面の外にある。** `shown()` は画面から 200px 以上 外れたものを候補から外す。
  前の画面の裏に残ったボタンを押す事故を防ぐためだが、内側にスクロール容器を
  持つ一覧では、下まで送ると上のほうの項目が押せなくなる。
  `p.scrollTo('目当ての文字')` で寄せてから押す
- **`role="button"` の無い `<div onClick>`。** 候補は `button` `a[href]`
  `[role="button"]` などに絞ってある。React の `<div onClick>` はここに入らない。
  選択肢に見えるのに押せないので、`p.eval` で直に押す

```js
await p.eval(() => [...document.querySelectorAll('div')]
  .find((e) => e.textContent.trim() === 'ぼうし')?.click());
```

⚠️ 候補を広げて解決しようとしない。緩めた瞬間、裏に隠れている前の画面の
ボタンを押しはじめる。撮れる絵が静かに狂うほうが、押せない不便より高くつく。

## 1-4. `scrollTo` は、寄せられなければ落ちる

⚠️ 2026-08-30 まで、`scrollTo` は当たらないと **`false` を返して黙って先へ進んで
いた。** シナリオは戻り値を捨てるので、寄せたつもりの画面が動かないまま次の
`shot()` が撮られる。マイ漢字タウンのマニュアルで、設定画面の同じ絵が 4 枚並んだ。

```js
await p.scrollTo('学習の量');   // 当たらない → 何も起きない
await p.shot('29-settings');    // さっきと同じ絵が撮れる
```

「同じ絵」の警告は出る。ただし出るのは 3 手あとで、しかも
「押せていない可能性がある」と、**押した側のせいに読める。** 原因は寄せた側なので、
そこから遡ることになる。`click` と同じように、当たらなかったその行で落とすようにした。

```
[main] 寄せられなかった: そんな文字はどこにもない
  いま画面にある字: ようこそ！ / マイ漢字タウン / … / 今日のミッション / …
  当たらないときは、まず ルビを外した字で書いているか確かめる（上の 1 節）。
  寄せられなくても続けてよいときだけ scrollTo(text, { optional: true })。
```

画面にある字が並ぶので、書いた文字列のほうが違っていれば その場で分かる。
**寄せられなくても構わないとき**（あってもなくてもよい節へ寄せるときなど）は
`{ optional: true }` を渡す。`click` と同じ約束。

### ふるいに、ふりがなを数えない

当てるほうも直した。`scrollTo` は入れ物を掴まないよう「子が 6 つ未満」で
ふるいにかけているが、**`<ruby>` は 1 語に 1 つ増える。** 数に入れると、
ふりがなを振った見出しほど先にはじかれる ── いちばん寄せたいものが、
いちばん当たらない。

マイ漢字タウンの「今日のミッション」は `children` が 7 で、**7 つとも `<ruby>`**
だった（2026-08-30 に実測）。ふりがなは字の飾りであって入れ物の構造ではないので、
数から外した。

⚠️ 正直に書いておくと、**この 2 つめの直しで撮れる絵が変わる例は、まだ実際には
出せていない。** マイ漢字タウンは内側の入れ物も動かない作りで、当たっても
当たらなくても画面が変わらなかった。はじかれること自体は測ってあるが、
「これで直った」と言えるのは 1 つめ（黙って進まない）のほうだけである。

## 2. 押したあと、画面が変わったことまで確かめる

押せたことと、画面が進んだことは別。押せてはいるが状態が変わらない、という失敗がある。
節目では `clickTo` を使う。

```js
await p.clickTo('スコアアタック', '学年をえらぶ');   // 出るまで待って、出なければ落ちる
await p.shot('02-select', { expect: '3年' });        // 撮る前にもう一度確かめる
```

いきなり全部を撮ろうとせず、1画面ずつ `buttons()` と `text()` を出して確かめながら進む。

## 3. アニメーションが終わるまで待つ

600ms では足りない。まだ出ていない要素を撮り落とした。2,200ms で安定した。
`open()` は既定でここまで待つ。画面遷移のあとも 1,500ms 前後は置く。

`shot()` は撮ってから 280ms 後にもう一度撮り、絵が同じになるまで繰り返す。
それでも止まらない画面は、演出が続いている。`p.freeze()` で止めてから撮るか、
演出そのものを撮る1枚と割り切る。

## 4. お祝いのモーダルが、見せたい画面を隠す

結果画面を撮ろうとすると、レベルアップの演出が手前に出て、肝心の順位表が
ぼやけた背景になってしまう。閉じてからもう1枚撮る。

```js
await p.shot('09-levelup');                      // お祝いはお祝いで1枚
await p.clickTo('やったー！', 'ランキング');
await p.shot('10-ranking', { expect: '1い' });   // 本命
```

## 5. 縦に長い画面は、ビューポートを伸ばして1枚に収める

ホーム画面のように上から下まで見せたいものは、`p.resize(390, 1900)` してから撮る。
`fullPage: true` はスクロール容器を持つアプリだと効かないことがあるので、
まずビューポートを伸ばすほうを試す。

内側にスクロール容器がある画面は `p.scrollTo('目当ての文字')` で寄せる。

伸ばしたままにすると次の画面まで縦長になる。撮ったら戻す。

## 6. 画面に出る URL を本番と同じ見た目にする

QR コードや共有 URL を表示するアプリだと、`http://127.0.0.1:4180/...` が
そのまま写りこむ。記事の画像としては具合が悪い。

撮影のあいだだけ、本番のホスト名をローカルに向ける。

```bash
echo "127.0.0.1 <user>.github.io" >> /etc/hosts
node <skill>/scripts/serve.mjs dist 80 /<repo>/
# --base http://<user>.github.io/<repo>/ で撮る
```

ポート 80 で配るのは、URL に `:8080` を出さないため。
これはアプリの本当の配信先なので、見た目を偽っていることにはならない。

## 7. P2P（みんなであそぶ）を撮るには、シグナリングサーバを手もとに立てる

外部のシグナリングサーバに到達できない環境では、へやを作った瞬間に
「接続エラー」で止まる。`scripts/peer-server.mjs` の先頭に手順が書いてある。

要点は3つ。

- `npm i --no-save peer` して `node <skill>/scripts/peer-server.mjs 9000`
- アプリ側の接続先を `127.0.0.1:9000` に一時的に差しかえ、
  CSP の `connect-src` に `ws://127.0.0.1:9000` と `http://127.0.0.1:9000` を足す。
  足さないとブラウザが接続をはじく
- 差しかえたらビルドし直す。撮影後に必ず戻し、`git status` と `git diff` で
  差分に残っていないか確かめる。ここを戻し忘れると本番が壊れる

## 8. `--no-save` は一度にまとめて入れる

`npm i --no-save playwright` のあとに `npm i --no-save peer` とすると、
あとから入れたほうが前のものを消してしまう。`npm i --no-save playwright peer` と書く。

## 9. マルチプレイは、本当に複数台つないで撮る

`open()` を人数ぶん呼ぶ。それぞれ独立したブラウザのプロファイルになるので、
保存データも混ざらない。合成した画像より、実際につないだ画面のほうが説得力がある。

Qalc の回はリーダー1台と子ども5台で、入室の申しこみから結果発表まで通して撮った。

## 10. 自動で問題を解かせるときは、正答率が不自然にならないようにする

学習アプリの記録画面を撮るには、実際に問題を解く必要がある。
問題文を読んで答えを計算し、キーを順に押す形になるが、次の2つに気をつける。

- 速く押しすぎると誤答が量産される。正解した瞬間に次の問題へ進む作りだと、
  押している途中で画面が切り替わり、初回正答率が数パーセントまで落ちた。
  1問ごとに 900ms ほど置いて、答えを入れ終えてから 150ms 待って決定を押す
- わざと数問だけまちがえる。「まちがえた問題」の一覧や復習の機能を
  撮りたいなら、全問正解では何も出ない。最初の2問だけずらして答え、
  そのあと正しく答え直す

## 11. 撮影用のスクリプトはリポジトリの中に置き、終わったら消す

`node_modules` の解決の都合で、シナリオファイルはリポジトリの中に置くことになる。
`.tmp-shots/` のような分かる名前にして、納品前に必ず消す。
`git status` にスクリプトが残っていないか確かめる。

## 12. 記事に載せる機能は、撮る過程で必ず実機を踏む

Qalc の回は、これで本番が壊れていることに気づいた。
「じんとりバトル」を撮ろうとしたら、開始した瞬間に全端末がまっ白になった。
インポートもれで、そのモードに入ると必ず落ちる状態だった。

動かない機能を紹介する記事を出してはいけない。
見つけたら、記事より先にそれを報告する。直せるなら直して、
別のコミットに分けたうえで「公開の前にこの修正を反映してください」と伝える。

`--strict` を付けて走らせると、画面のエラーが1件でもあれば異常終了する。
最後の1回はこれで通す。

## 13. 撮ったあと report.json を記事作りに使う

`report.json` には、1枚ごとに「そのとき画面に何が書いてあったか」「直前に何を押したか」
「ファイルの大きさ」が入っている。納品する `docs/note/README.md` の画像対応表は、
記憶ではなくこれを見て書く。

画像が 3MB を超えていたら警告が出る。note に上げる前に小さくする。

## 14. 撮ったのに記事で使わない画像を、置き去りにしない

`docs/note/images/` は記事だけのものではない。トップページのカードで切り替わる
サムネイル6枚も、ここから選んで 640×400 の 16:10 に切って作られる。

とはいえ、記事から一枚も参照されない画像が残っていると、あとで見た人には
それが撮り損ねなのか、意図して残したのかが分からない。実際、マイ漢字タウンの
`docs/note/images/` には、記事に出てこない画像が11点残っている。

使わないと決めたものは消す。サムネイルのために残すなら、納品の README に
「サムネイル候補」として理由つきで挙げる。

サムネイルに向くのは、余白の少ない、横に切っても中身が残る絵。
撮る段階で、操作の流れを端から端まで散らした6枚を意識しておくと選びやすい。

## 15. 1枚目の画像が、そのアプリの顔になる

記事の1枚目は、紹介ページの SNS カード画像になる。ホーム画面など、
そのアプリらしい絵を1枚目に置く。

ただし Vite で `dist/` だけを配っているリポジトリでは、`docs/note/images/` が
配信物に入らないため、カード画像がサイト共通の絵に落ちる。納品前に確かめる。

```bash
curl -sI https://<slug>.giga-school.com/docs/note/images/01-home.png | head -1
```

届かないなら、1枚目だけを配信物（`public/` など）に足せば戻る。
20枚ぜんぶ入れると、dist の大きさを見張っている品質ゲートに引っかかる。

## 16. 撮り直すときは、名前を変えない

`--out` に前と同じディレクトリを指すと、`capture.mjs` は前回の `report.json` を読んで、
どの画面が変わったかを最後に出す。

```
  前回と比べて  変わった4／同じ17／新しい2／撮らなかった0
    変わった  05-drill.png  ドリル一覧 6年 わり算のひっ算
    新しい    22-boss.png
    変わった画面については、本文の書きぶりが古くなっていないか読み直す
```

ファイル名を前と同じにしておけば、記事の参照はそのまま生きる。
名前を変えると本文の画像が全部切れるので、番号の意味を保ったまま上書きする。

撮り直しでいちばん多い失敗は、画面が変わったのに本文が前のままになること。
人が読んでも気づきにくい。この一覧に出た画像は、必ず本文と読み合わせる。

撮らなかった画像は消さない。記事がまだ参照している。
