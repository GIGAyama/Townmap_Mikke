# 文体ガイド（連載「教室で使えるかもしれないもの作り」）

厳守ルールが書いてある散文の正本はこのファイル。SKILL.md には写しを置かない。

ただし機械の側にはもう一つ正本がある。XXX_automatic の `config/note-style.json` で、
投稿ランチャーの `note-lint.mjs` が同じ基準を当てている。数値やリストを変えるときは、
このファイルと `config/note-style.json` と `scripts/lint-article.mjs` の DEFAULT_STYLE を
そろえて直す。ひとつだけ直すと、書き手が二つの検査から違うことを言われる。

書き手は GIGA山。小学校の先生が、同じ小学校の先生に向けて、自分の作ったものを紹介する連載。
読み手は忙しい先生方で、「ICTは難しそう」と感じている層にも届かせたい。

手本は Qalc の記事（`GIGAyama/Qalc` の `docs/note/qalc-note-article.md`）。
本文 7,590字、画面 21点。以下の目安はすべて、この記事が通ることを確かめて決めてある。

## 立ち位置

作者本人が書く。だから「作った理由」「あえてそうしなかったこと」を書ける。
そこがこの連載の強みなので、機能の説明だけで終わらせず、なぜその作りにしたのかを添える。

いっぽうで、教室での出来事を実体験として書いてはいけない。
作者の実践記録ではないので、「使ってみたら子どもたちが〜」と書くと嘘になる。
書けるのは「こうなればいいと思って作った」「〜だと思います」まで。
実際の授業での様子は、書き手が自分で足すところ。

# 厳守ルール

このルールが目指しているのは一つだけで、読み手が「人が書いた文章だ」と感じること。
記号を禁じているのも装飾の趣味の問題ではなく、記号でつないだ文章は考えた跡が消えて
機械が並べたものに見えるから。以下はすべてその一点から出ている。

## A. 記号と表記

A1. 太字（`**`）を使わない。装飾ではなく文章の力で強調する
A2. 斜体、表、水平線を使わない。表は note では表示されない
A3. Markdown は見出し（`#`）だけ。リンクも `[文字](URL)` にせず、URL をそのまま置く
A4. 区切りの記号を使わない。`→` `⇒` `／` `▲` `▼` `▶` `◀` `※` `＞` `≫`
A5. コロン `：` を使わない。「目的：」のようなラベル出しはしない。
　　半角コロンのあとに空白を置く書きかたも禁止
A6. 箇条書きは「📖【利用者向け】使い方のガイド」の番号つき手順だけ。
　　それ以外は文章で書く。並べれば伝わるわけではない
A7. 絵文字は見出しだけ。本文には入れない
A8. かぎかっこ「」は、アプリ名や画面に出てくる言葉を指すときだけ。
　　強調や定義のために使わない。手本は1,000字あたり3.4個
A9. かっこ（）で補足しない。補足したくなったら次の一文にする。
　　手本の本文にはかっこが一つも無い。アプリ名を書く題だけで使っている

## B. 語彙

B1. 前置きの宣言を書かない。「結論から言うと」「本記事では」「〜を解説します」「早速ですが」
B2. 安全クッションを書かない。「一般的に」「多くの場合」「一概には言えませんが」
　　「状況によって異なります」。情報が増えないうえに、書き手の顔が消える
B3. 抽象語で押し切らない。禁止するのは「重要」「効率的」「革新的」「画期的」
　　「シームレス」「ソリューション」「エビデンス」。
　　何がどうなるかを動詞で書く。「丸付けに追われなくなる」「その場で間違いに気づける」
B4. ただし「最適」と「活用」は禁止しない。「個別最適な学び」「ICTを活用する」は
　　学習指導要領の言葉として現場で使われていて、手本の記事にも入っている。
　　言葉狩りにすると、正しい記事のほうが落ちる
B5. 同義語の言い換え連打をしない。「重要で、大切で、欠かせない」は一度で言い切る
B6. 抽象的なまとめを繰り返さない。「まとめると」「要するに」「総じて」、同内容の再掲
B7. 締めの定型句を書かない。「参考になれば幸いです」「まずは小さく始めましょう」
B8. 専門用語を日常の言葉に置きかえる。

```
デプロイ            公開の設定
ローカルストレージ  その端末のなかだけに残ります
WebRTC / P2P        端末どうしの直接のやりとり
API                 外部のサービスとのやりとり
リポジトリ          公開しているファイルの置き場
キャッシュ          端末に一度読みこんだもの
レスポンシブ        画面の大きさに合わせて
インターフェース    画面のつくり
アルゴリズム        しくみ
変数・配列・関数・オブジェクト    出さない
```

## C. リズム

C1. 文の長さを均一にしない。短い文と長い文を混ぜる。手本は平均33字
C2. 同じ型を続けない。断定して理由、断定して理由、と並ぶと機械の口調になる
C3. 同じ文末を三つ続けない
C4. 接続詞は必要最小限にする
C5. 一人称は「私」で統一する。「筆者」「私たち」を混ぜない。です・ます調

## D. 内容

D1. 教室での出来事を実体験として書かない
D2. 効果を言い切らない。「いちばん盛り上がる時間になる」ではなく「〜だと思います」
D3. 裏の取れていない数字を書かない。数えられるものは数える
D4. 元の資料にない数字、固有名詞、事例を足さない
D5. 取材で聞いていない考えを、書き手の考えとして書かない。
　　事実は資料から、考えは取材から。どちらの裏づけも無い一文は消す。
　　書き手の言葉は、どこか一つそのまま残す
D6. 収益化の導線を入れない。地方公務員法38条にもとづく確認が済むまでは、
　　有料記事、メンバーシップ、アフィリエイト、投げ銭のいずれも書かない

## この連載での例外

上のルールは、AIらしさを消すための一般則を note の連載に合わせたもの。
次の三つは「AIっぽい」から外れるが、この連載では必要なので残す。

- 見出しの `##` と、見出し先頭の絵文字。note が見出しから目次を作るため
- 使い方のガイドの番号つき手順
- アプリ名や画面の文言を指すかぎかっこ

# 呼びかた

子どものことは「子どもたち」。「児童」「生徒」は使わない。
読み手は「先生」「先生方」。

# 構成

```
# 教室で使えるかもしれないもの作り #◯ （キャッチーなタイトル）「アプリ名」

## 🏫 はじめに                      600〜1,200字
## 📱 このアプリでできること        1,200〜2,200字
（目玉が収まらないときだけ、ここに2本まで足す）
## ✨ 導入のメリット                700〜1,400字
## 🛠️ 【管理者向け】導入手順        600〜1,400字
## 📖 【利用者向け】使い方のガイド  700〜1,800字
## 📝 まとめ                        400〜900字
## 🏷 ハッシュタグ
```

節ごとの字数は書くときの目安で、外れていても直さなくていい。
手本の記事も、はじめにが 488字、できることが 1,047字で目安を下回っている。

見出しの並びと言葉は変えない。機械がこの並びを前提に目次と検索の索引を作る。

## タイトルの型

`「（読み手が困っていること）」（アプリの持ち味）アプリ「名前」`

- #9 … 「4択」じゃ届かない定着を。経験値でハマる計算学習アプリ「Qalc（カルク）」
- 今回 … 「せんせい、わかりません」で止まらない。考える図が出てくる計算学習アプリ「Qalc（カルク）」

かぎかっこが2組。連載名を除いて50字まで。
連載番号は推測で埋めない。着手のときに書き手へ聞く。
聞けないまま書きはじめたら `#◯` のままにして、納品時に伝える。

## 🏫 はじめに

読み手が抱えている困りごとに、まず寄りそう。
「〜ではありませんか」「〜ですよね」「〜ではないでしょうか」と問いかける形が合う。

そのあとで、このアプリがその困りごとにどう効くのかを一言で置き、URL を出す。

最初の一段落は、そのまま検索結果とSNSの説明文になる（110字で切られる）。
問いかけで始めるのは連載の型だが、その一文だけで何のアプリの記事か伝わるほうがいい。

前作がある場合は、ここで前作との地続きを作る。

## 📱 このアプリでできること

機能を並べるのではなく、子どもや先生が実際に使っている場面が浮かぶように書く。
画面のスクリーンショットはここから入れはじめる。

## ✨ 導入のメリット

「三つのいいことが期待できます。」で始めて、
「一つ目は、〜ことです。」「二つ目は、〜」「三つ目は、〜」と続ける型。
それぞれ一段落。得られるのは機能ではなく「心のゆとり」と「教育効果」。

型がはっきりしているぶん、いちばん機械的な文章になりやすい。
三つの段落の長さをそろえない。理由の書きかたも変える。

## 🛠️ 【管理者向け】導入手順

情報担当の先生に確認されることを、先に全部書いておく。ここは記事の中でいちばん、
書いたことがそのまま外で使われる節になる。三つは必ず入れる。

- 校内フィルタリングで許可が必要なアドレス。いま配信に使っているホスト名を書く。
  古いアドレスのまま書くと、学校が的外れな許可申請をすることになる
- アカウントが要るかどうか。「アカウントもログインもいりません」のように、
  その言葉で書く。書いていないと、サイトの一覧にも項目として出せない
- 記録がどこに残るか。「その端末のなかだけに残ります」「外に送られることはありません」

共用端末での注意と、端末ごとの癖もここに。

## 📖【利用者向け】使い方のガイド

ここだけは番号つきの手順で書く。迷いようがない粒度にする。

## 📝 まとめ

ICT を使うことで生まれる「子どもと向き合う時間」の話でしめる。
効率化そのものが目的ではない、という筋を通す。

最後は挑戦する先生への応援で終わる。連載の署名にあたる一文。

> 一歩踏み出そうとする先生を、私はいつでも全力で応援しています。

## 🏷 ハッシュタグ

記事のいちばん最後。見出しのあとに、タグだけを並べた一行を置く。

```
## 🏷 ハッシュタグ

#小学校 #小学校教員 #算数 #計算 #GIGAスクール #ICT教育 #1人1台端末 #教育 #授業づくり #学級経営 #タブレット学習 #Chromebook #iPad #個別最適な学び #特別支援教育 #Qalc
```

10〜16個。この行より下に段落を置かない。置くと機械がタグの行を見失う。
行の中に `#` で始まらない語を混ぜても、行ごと拾われなくなる。

この節は note のためだけのもので、giga-school.com の紹介ページには出ない。
組み立てのときに、末尾がタグだけの段落になっていれば見出しごと落としている。

選びかた。

- 学校の言葉から選ぶ。小学校、小学校教員、教育、授業づくり、学級経営、
  GIGAスクール、ICT教育、1人1台端末、個別最適な学び、特別支援教育
- その回の教科と機能を足す。算数、計算、漢字、音読、自主学習、宿題
- 端末の名前は入る。Chromebook、iPad、タブレット学習
- アプリ名を最後に1つ入れる。検索する人は少ないが、連載の中でつながる
- `#プログラミング` `#個人開発` は入れない。届けたいのは開発者ではなく先生

# 画像のキャプション

画像の直後に、短い一行を置く。装飾記号は付けない。60字まで。

```
![ホーム画面](images/01-home.png)

トップページ。レベルと称号、コイン、連続学習日数が一画面にまとまっています。
```

名詞だけの短いものと、一文の説明を混ぜると単調にならない。
note ではキャプション欄に移すので、本文から浮いていて問題ない。

120字を超えると、紹介ページの組み立てがキャプションだと見分けられなくなり、
同じ文が画像の下と本文とに二度出る。

# 分量

7,000〜12,000字。画面の点数が多い回ほど伸びる。手本は 7,590字。
`config/note-style.json` の `charRange` も同じ値にそろえてある。

# やりがちな失敗

- 太字を散らして、広告のようになる
- 「〜できます」を並べて、なぜそうしたのかを書き忘れる
- 効果を言い切る。作者の見立てとして書く
- 記号でつないで、文章になっていない
- 導入手順を後回しにする。ここが読まれないと、そもそも使ってもらえない
- 三つの段落を同じ長さ、同じ型で書いて、機械が並べたように見える
- フィルタリングのアドレスを、前の記事からそのまま写す
