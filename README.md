# 🗺️ みっけ！ | クラス単位マルチテナント版 協働学習プラットフォーム

**「誰もが迷わない直感UI × 先生の管理をゼロにする自動化 × 対話が生まれる協働空間」**

みっけ！は、Google Apps Script (GAS) と React で構築された、教育現場のためのマップ型協働学習プラットフォームです。
児童は先生が用意した**地図の画像**に、見つけたものを**ピン**として貼り、写真・メモ・スタンプで記録します。ほかの子のピンを見てコメントしたり、👍 を送ったり、チャットで話し合ったりできます。先生は、その活動を管理画面から一覧・分析・印刷できます。

外部サーバー・DB・有料 API は一切使わず、完全無料で運用できます。

### 配り方

**先生おひとりずつが、ご自分の Google アカウントで公開して使う形**です。共通の入口はありません。

| | |
|---|---|
| 先生の手数 | スプレッドシートをコピー → メニューを 1 回押す → **ウェブアプリを 1 本デプロイ** |
| データの置き場所 | 先生ご自身のドライブの、**そのスプレッドシート 1 つ**の中 |
| 児童の入口 | 先生が公開した `/exec` の URL |
| 本人確認 | `Session.getActiveUser()`（＝「アクセスできるユーザー: 同一ドメインの全員」が必須） |
| 運営者の設定 | **ありません**（アプリアカウントも OAuth クライアント ID も要りません） |

> **2026-08-25 に、共通デプロイ版（クラスコード付きの共通 URL / GIS の ID トークン / 中央レジストリ）と、
> 貼り付けで入れた旧バインド型（`Users_名簿` シート）を廃止しました。**
> 詳しくは「更新履歴」を参照してください。

実装されている機能をすべて列挙しています。「書いてあるのに無い」「あるのに書いていない」が起きないよう、コードと 1 対 1 で対応させています。

### 👩‍🏫 先生ができること

#### スプレッドシートのメニュー「みっけ！」

| できること | 具体的な内容 |
|---|---|
| **はじめの設定（先生として登録）** | 押した人を `Settings` シートの `ownerEmail` に記録し、必要なシートを作る。**このファイルの編集権を持つ人にしか押せない**ので、児童が先生になることはない |
| **シートを点検する** | 見出し・列の並びがアプリの想定どおりかを見る。**1 セルも書き換えない** |
| **シートを直す（足すだけ）** | 足りないシート・列を足し、見出しの表記ゆれをそろえる。**消す・動かすはしない** |
| **この学級の設定を見る** | 学級名・参加の受付・承認の要否・人数 |

#### 管理パネル（アプリ本体の「管理パネル」ボタン）

5 つのタブがあります。

| タブ | できること |
|---|---|
| **📊 学習分析** | 児童を選ぶと、その子の**ピン数・発言数**、**刺したピンの一覧**（写真・タイトル・メモ）を表示。**🖨️ 印刷**でそのままポートフォリオとして配布可能。**✨ AI ポートフォリオ生成**（Gemini）で「興味関心の傾向 / 素晴らしい点 / 先生からのメッセージ」を自動作成 |
| **🗺️ 単元・設定** | **チャットの ON / OFF**、**絵文字スタンプピンの ON / OFF とカスタマイズ**（最大 24 個）、**今の単元に地図を追加**（タブが増える。「いま表示している地図のピンを引き継ぐ」チェック付き）、**新しい単元を開始**（児童の画面が自動で切り替わる） |
| **👥 名簿登録** | `メールアドレス, 表示名, 班名` を 1 行 1 名で貼り付けて一括登録（1 回あたり最大 200 名）。**一括登録した児童は承認不要で即参加**になる |
| **🏫 学級の管理** | **参加申請の承認**（選んで承認 / 全員まとめて承認）、参加している人の一覧と「外す」、**学級の名前**、**参加受付の ON / OFF**、**承認制の ON / OFF**、**シートの点検と修整** |
| **⚙️ AI 設定** | Gemini API キーの登録。キーは**そのクラスのスプレッドシートの `Settings` シートにのみ**保存され、ScriptProperties には置かない |

> AI 機能は**任意**です。API キーを設定しなければ、AI 以外のすべての機能がそのまま使えます。

### 🔁 自動で行われること

- **単元の切り替え追従**: 先生が新しい単元を開始すると、児童の画面は再読み込みなしで自動的に新しい単元へ切り替わる
- **定期同期**: 児童は 15 秒ごと、先生は 10 秒ごとにサーバーと同期。**タブが非表示のときは同期しない**（クォータ節約）
- **書き込み直後の保護**: 保存直後の同期が、送信したばかりのピンを一時的に巻き戻さないようガードしている
- **混雑時の自動リトライ**: サーバーが書き込みロックで混んでいる場合（`LOCK_BUSY`）、指数バックオフで最大 3 回自動リトライ
- **承認待ちの自動入室**: 承認制のとき、児童の画面は 20 秒ごとに状態を確認し、承認された瞬間に切り替わる（再読み込み不要）

## 🏗️ アーキテクチャ

```
先生: スプレッドシートをコピー
      → メニュー「みっけ！ ＞ はじめの設定」で Settings.ownerEmail に自分を記録
      → 「デプロイ ＞ ウェブアプリ」（自分 / 同一ドメインの全員）
      → 出てきた /exec の URL を学級に配る

児童: その URL を開く → Session.getActiveUser() で本人が分かる
      → 名簿（Members シート）に載っていて active なら学級の地図へ
      → 載っていなければ参加の申請 → 先生が承認するまで何も見えない
```

先生かどうかは **`Settings` シートの `ownerEmail`** と **名簿の `role=teacher`** だけで決めます。
`Session.getEffectiveUser()` は「自分として実行」では**誰が開いてもデプロイした先生**を返すので、
**本人確認には使いません**（使った瞬間に学級全員が先生になります）。
`ownerEmail` を書けるのは、スプレッドシートのメニュー（＝そのファイルの編集者しか出せない）と、
`active !== effective` が観測できたとき（＝「自分として実行」が確定したとき）だけです。

## 🚀 入れかた（先生おひとりで完結します）

準備するものは Google アカウント 1 つだけです。運営者の設定はありません。

### 1. スプレッドシートをコピーする

配布用スプレッドシートのコピーリンクを開き、「コピーを作成」を選びます。

> **コピーリンクはまだ用意できていません。** テンプレートの作り方は
> [`docs/copy-distribution.md`](docs/copy-distribution.md) にあります。
> 用意ができるまでは、下の「A-1′. 貼り付けで入れる」でお願いします。

#### 1′. 貼り付けで入れる（コピーが禁止されている学校向け）

1. 新しいスプレッドシートを作り、「拡張機能 ＞ Apps Script」を開く
2. 既定の `コード.gs` に `Main.gs` を貼り、「＋ ＞ スクリプト」で
   **`Db.gs` / `Schema.gs` / `Tenant.gs` / `Bound.gs` / `Gemini.gs`** を足して貼る
3. 「＋ ＞ HTML」で `App` を作り、`App.html` を貼る
4. 「プロジェクトの設定」で `appsscript.json` をエディタに出し、
   本リポジトリの **`appsscript.json`** の中身にする

### 2. 「はじめの設定」を 1 回押す

スプレッドシートに戻ると、上のメニューに **「みっけ！」** が出ます
（出ないときは再読み込みしてください）。
**「はじめの設定（先生として登録）」** を押すと、

- 必要なシート（`Members` / `Settings` / `Units_単元` / `Pins_ピン` …）が作られ
- **押した方が、この学級の先生として `Settings` シートに記録され**
- シートの作りの点検結果が出ます

> **押した人が先生になります。** メニューはそのファイルの編集権を持つ人にしか出ないので、
> 児童が先生になることはありません。児童にこのスプレッドシートを共有しないでください。

### 3. ウェブアプリとして公開する

「拡張機能 ＞ Apps Script ＞ デプロイ ＞ 新しいデプロイ ＞ ウェブアプリ」で、

| 項目 | 値 |
|---|---|
| 次のユーザーとして実行 | **自分** |
| アクセスできるユーザー | **同一ドメインの全員** |

- 「自分」にすると読み書きが先生の権限で走るので、**児童はスプレッドシートへのアクセス権を 1 つも持たなくて済みます**。
- 「アクセスできるユーザー」を **「全員」にしないでください。** `Session.getActiveUser().getEmail()` が
  空になり、**先生ご自身も含めて誰も入れなくなります**（画面にその旨が出ます）。
- **やり直すときは「デプロイを管理 ＞ 既存のデプロイを編集」**。「新しいデプロイ」を作ると
  `/exec` の URL が変わり、配ったリンクが全部切れます。

出てきた `/exec` の URL を学級に配れば準備完了です。

### 4. シートを触ってしまったとき

列は**見出しの名前**で読み書きしているので、列を足したり並べ替えたりしても動きます。
困るのは見出しの行ごと消えたときで、そのときは
メニュー「みっけ！ ＞ シートを点検する」（または教師用コンソールの「学級の管理 ＞ シートの点検」）が
どこがどうなっているかを出します。
**「シートを直す（足すだけ）」は足りないシートと列を足すだけ**で、消したり動かしたりはしません。

1. 配られたスプレッドシートをコピーする
2. メニュー「みっけ！」＞「はじめの設定（先生として登録）」を 1 回押す

## 🔐 セキュリティ設計（信頼境界）

- **信用できる入力は 1 つだけ**: `Session.getActiveUser().getEmail()`。
  `e.parameter`・`google.script.run` の引数はすべて改ざん可能として扱う
- **`Session.getEffectiveUser()` を本人確認に使わない。** 「自分として実行」では
  **誰が開いてもデプロイした先生**を返すので、使った瞬間に学級全員が先生になる
- **先生は 2 つの経路でしか決まらない**: `Settings` シートの `ownerEmail`（メニューの
  「はじめの設定」＝そのファイルの編集者しか押せない、または `active !== effective` が
  観測できたとき＝「自分として実行」が確定したときだけ書かれる）と、名簿の `role=teacher`
- **本人が特定できないときは、誰も通さない。** 「アクセスできるユーザー」が
  「同一ドメインの全員」でないと `getActiveUser()` は空になる。そのときは
  `BOUND_NO_IDENTITY` で止め、直し方を画面に出す（fail-closed）
- すべての API はサーバー側で「①本人確認 → ②名簿照合(status=active) → ③役割チェック
  → ④行所有者チェック」を通す。フロントの出し分けは防御とみなさない
- **他児童のメールアドレスは児童側に一切露出しない**（児童向けレスポンスでは email を
  `sha256(email)` 先頭 12 桁の匿名 ID に置換）
- 書き込み者の email は常にサーバー側で決定する（フロントから渡された email は使わない）
- **児童はスプレッドシートへのアクセス権を 1 つも持たない。** 読み書きは先生の権限で走る
- **児童が書いた文字は、セルに入る手前で無害化する**（先頭が `= + - @` なら `'` を足す）。
  これが無いと、児童が「なまえ」に `=IMPORTXML(…)` と書くだけで、先生がシートを開いた
  瞬間に学級のデータが外部へ流れる
- 画像は Drive を使わず、圧縮した Data URL を `Images_画像` に**40,000 文字ずつ分割して**保存
  （Drive 権限も共有リンクも発生しない）
- **AI へ送る文字列は必ず仮名化を通す。** 組み立ては `corePortfolioPrompt_` の 1 本だけ
  （2 か所に持っていた頃は、片方だけ直すともう片方から実名が流れた）

## 🗄️ データの持ち方

### 学級のスプレッドシート（先生所有・スクリプトが束ねられているファイル）

| シート | 列 |
|---|---|
| `Members` | email / displayName / role / status(`active`,`pending`,`removed`) / number / groupId / joinedAt |
| `Settings` | key / value（`ownerEmail` / `className` / `joinOpen` / `requireApproval` / `geminiApiKey`） |

## 📲 GitHub Pages（導入の案内ページ）

`docs/` は `townmap-mikke.giga-school.com` で配る**導入の案内ページ**です。アプリではありません
（アプリは先生ごとの `/exec` で動きます）。

- Service Worker は `mikke-shell-` で始まる**自アプリのキャッシュだけ**を削除します。
  旧配信元の `gigayama.github.io` は多数のアプリが同一オリジンを共有していたため、これは必須の制約です
- 版は `docs/` の中身から自動で採番されます（`npm run build:sw`）。手で直さないこと

### リリース手順

**`docs/` を直したとき**

1. **`npm run build:sw`** を実行する。`docs/sw.js` の `APP_VERSION` は
   配信物の中身から自動で採番されます（手で直さないこと）。
2. `npm run check` が通ることを確かめて push → GitHub Pages に反映。
   CI の `npm run check` が `build:sw --check` を含むので、上げ忘れは赤くなります。

**`.gs` / `App.html` を直したとき**

main への push で `deploy.yml` が `clasp push` と既存デプロイの差し替えまで行います。
宛先はシークレット（`GAS_SCRIPT_ID` / `GAS_DEPLOYMENT_ID`）で決まる**1 本だけ**です。

- 手で「新しいデプロイ」を作らないこと（`/exec` の URL が変わり、配ったリンクが全部切れます）。
  やり直すときは「デプロイを管理 ＞ 編集 ＞ バージョン: 新バージョン」。
- **配ったテンプレートのコピーには届きません。** 先生の手元にあるのは独立した
  プロジェクトです。直しを届けるにはテンプレートを作り直して配り直すか、
  先生に貼り直しをお願いします。

## ⚙️ 運用上の注意

- **データ主権**: 学級の記録は先生所有のスプレッドシート 1 つの中だけにあります。
  制作者も、ほかの先生も見られません。学年が終わっても先生のドライブに残ります。
- **児童にそのスプレッドシートを共有しないでください。** 共有しなくても、児童はアプリから使えます
  （読み書きは「自分として実行」で先生の権限で走るため）。
- **クォータ**: すべての読み書きが先生の割り当てを消費します。
  同時実行 約 30 / 1 日の実行時間 90 分（無料アカウント。Workspace はもっと多い）。
  書き込みは ScriptLock で直列化し、保持区間は `appendRow` 1 回程度に最小化してあります。
  競合時はフロントが指数バックオフで最大 3 回リトライします。
- **URL が学外に漏れたとき**: Apps Script の「デプロイを管理」でそのデプロイをアーカイブし、
  新しいデプロイを作って配り直してください（URL が変わります）。記録はシートに残ります。
- **Gemini API キー**: 学級ごとにそのシートの `Settings` に保存されます。
  学級をまたいで共有されません。設定しなければ AI 以外のすべてが使えます。
