# 🗺️ みっけ！ | クラス単位マルチテナント版 協働学習プラットフォーム

**「誰もが迷わない直感UI × 先生の管理をゼロにする自動化 × 対話が生まれる協働空間」**

みっけ！は、Google Apps Script (GAS) と React で構築された、教育現場のためのマップ型協働学習プラットフォームです。
児童は先生が用意した**地図の画像**に、見つけたものを**ピン**として貼り、写真・メモ・スタンプで記録します。ほかの子のピンを見てコメントしたり、👍 を送ったり、チャットで話し合ったりできます。先生は、その活動を管理画面から一覧・分析・印刷できます。

外部サーバー・DB・有料 API は一切使わず、完全無料で運用できます。

### 配り方は 2 通りあります

| | **A. コンテナバインド（いまの配り方）** | **B. 共通デプロイ（前の配り方。公開済みの学級のために残しています）** |
|---|---|---|
| 先生の手数 | スプレッドシートをコピー → メニューを1回押す → **1 本デプロイ** | 運営者が **2 本デプロイ**し、先生は共通 URL を開くだけ |
| データの置き場所 | 先生ご自身のドライブの、**そのスプレッドシート 1 つ**の中 | 先生所有のクラス DB スプレッドシート（アプリアカウントが編集者） |
| 児童の入口 | 先生が公開した `/exec` の URL | 共通 URL `https://townmap-mikke.giga-school.com/?c=クラスコード` |
| 本人確認 | `Session.getActiveUser()`（＝「アクセスできるユーザー: 同一ドメインの全員」が必須） | GIS の ID トークン検証（`Auth.gs`） |
| 運営者の設定 | **不要** | アプリアカウント・OAuth クライアント ID・ScriptProperties・GitHub Pages のシェル |
| 対応するコード | `Bound.gs` / `Schema.gs` | `Auth.gs` / `Registry.gs` / `TeacherApi.gs` / `StudentApi.gs` / `docs/class.html` |

**A と B は同じコードで動きます。** `Main.gs` の `doGet` が、スプレッドシートに束ねられているか
どうかと、その中身（`Members` シートに行があるか）を見て、自動で選びます。
**B ですでに公開してある学級は、そのまま動きます。**

> 👩‍🏫 **先生向けの、専門用語なしの操作マニュアルは [MANUAL.md](MANUAL.md) にあります。**
> この README は、アプリを**導入・運用する人（運営者）と開発者**向けの技術文書です。

## 📱 このアプリでできること（機能一覧）

実装されている機能をすべて列挙しています。「書いてあるのに無い」「あるのに書いていない」が起きないよう、コードと 1 対 1 で対応させています。

### 🧒 児童ができること

| できること | 具体的な内容 |
|---|---|
| **クラスに参加する** | 先生からもらった URL / QR を開き、Google でサインイン → **表示する名前**（ニックネーム可・必須）と**出席番号**（任意）を入れて申請。承認制が ON なら先生の承認待ちになり、**20 秒ごとに自動で状態を確認して、承認された瞬間に画面が切り替わる** |
| **ピンをさす** | 地図をタップした場所にピンを作成。**アイコン**（5 色のピン、または先生が設定した絵文字スタンプ）・**なまえ**（100 字まで）・**メモ**（1,000 字まで）・**写真**（端末のカメラ / アルバムから 1 枚）を登録 |
| **写真をつける** | 端末側で**長辺 600px・品質 0.7 に自動圧縮**してから送信。大きすぎる場合はさらに圧縮し、それでも収まらなければエラー表示 |
| **地図を見る（3 つのモード）** | ① **さわる・見る**（ピンをタップして詳細を開く）／ ② **かこんで見る**（地図を指でなぞって範囲を囲むと、その中のピンだけ一覧表示）／ ③ **ピンをさす**（タップした位置に新規作成） |
| **拡大・縮小・移動** | 2 本指ピンチ（タブレット・スマホ）、マウスホイール / トラックパッド（PC）、画面左下の ± ボタン。**いずれも最大 6 倍**、指やカーソルの位置が支点。「戻す」ボタンで元の表示に復帰 |
| **表示を絞り込む** | 画面上部で「**みんな / じぶんの班 / じぶん**」を切り替え（この切替は児童のみ表示。先生の画面には出ません） |
| **地図を切り替える** | 先生が同じ単元に複数の地図を追加している場合、上部にタブが出て切り替えられる（例：「探検前マップ」「探検後マップ」） |
| **友だちのピンを見る・反応する** | ピンの詳細で、作者名（表示名と班）・写真・メモを閲覧。**👍 リアクション**を付ける／外す。**コメント**を書き込む（コメントもリアクション可） |
| **みんなのひろば（チャット）** | 単元全体のチャット。ほかの人の発言への**返信**、発言への**👍** ができる。先生がチャットを OFF にしている間は送信欄が「チャットはオフになっています🔇」に変わる（**ピンへのコメントは OFF でも書ける**） |
| **わたしのきろく 📒** | 自分のピンだけを**新しい順に一覧**。**ことばで検索**でき、その場で「✏️ なおす」「🗺️ 地図で見る（その地図タブへジャンプ）」ができる |
| **自分の記録をなおす・消す** | 自分のピンはタイトル・メモ・アイコン・写真をいつでも書き直せる。削除も可能（確認あり）。**他人のピンは編集も削除もできない**（サーバー側で行の所有者を検証） |
| **ふりがな** | 児童が読む文言には `<ruby>` によるふりがなが付く |
| **アプリとして入れる** | 入口ページ（シェル）から「📲 アプリを入れる」でホーム画面に追加できる（PWA） |

| できること | 具体的な内容 |

#### 管理パネル（アプリ本体の「管理パネル」ボタン）

4 つのタブがあります。

| タブ | できること |
|---|---|
| **📊 学習分析** | 児童を選ぶと、その子の**ピン数・発言数**、**刺したピンの一覧**（写真・タイトル・メモ）を表示。**🖨️ 印刷**でそのままポートフォリオとして配布可能。**✨ AI ポートフォリオ生成**（Gemini）で「興味関心の傾向 / 素晴らしい点 / 先生からのメッセージ」を自動作成 |
| **🗺️ 単元・設定** | **チャットの ON / OFF**、**絵文字スタンプピンの ON / OFF とカスタマイズ**（最大 24 個）、**今の単元に地図を追加**（タブが増える。「いま表示している地図のピンを引き継ぐ」チェック付き）、**新しい単元を開始**（児童の画面が自動で切り替わる） |
| **👥 名簿登録** | `メールアドレス, 表示名, 班名` を 1 行 1 名で貼り付けて一括登録（1 回あたり最大 200 名）。**一括登録した児童は承認不要で即参加**になる |
| **⚙️ AI 設定** | Gemini API キーの登録。キーは**そのクラスのスプレッドシートの `Settings` シートにのみ**保存され、ScriptProperties には置かない |

> AI 機能は**任意**です。API キーを設定しなければ、AI 以外のすべての機能がそのまま使えます。

### 🔁 自動で行われること

- **単元の切り替え追従**: 先生が新しい単元を開始すると、児童の画面は再読み込みなしで自動的に新しい単元へ切り替わる
- **定期同期**: 児童は 15 秒ごと、先生・旧バインド型は 10 秒ごとにサーバーと同期。**タブが非表示のときは同期しない**（クォータ節約）
- **書き込み直後の保護**: 保存直後の同期が、送信したばかりのピンを一時的に巻き戻さないようガードしている
- **サインインの自動更新**: ID トークンは約 1 時間で切れるが、期限切れを検知すると自動で再取得してリトライする（児童の操作は不要）
- **混雑時の自動リトライ**: サーバーが書き込みロックで混んでいる場合（`LOCK_BUSY`）、指数バックオフで最大 3 回自動リトライ
- **オフライン時の表示**: 圏外ではキャッシュ済みのシェル、それも無ければ専用の `offline.html` を表示する

## 🏗️ アーキテクチャ

### A. コンテナバインド（いまの配り方）

```
先生: スプレッドシートをコピー
      → メニュー「みっけ！ ＞ はじめの設定」で Settings.ownerEmail に自分を記録
      → 「デプロイ ＞ ウェブアプリ」（自分 / 同一ドメインの全員）
      → 出てきた /exec の URL を学級に配る

児童: その URL を開く → Session.getActiveUser() で本人が分かる
      → 名簿（Members シート）に載っていて active なら学級の地図へ
      → 載っていなければ参加の申請 → 先生が承認するまで何も見えない
```

先生かどうかは **`Settings` シートの `ownerEmail`** と **名簿の `role=teacher`** だけで決めます。
`Session.getEffectiveUser()` は「自分として実行」では**誰が開いてもデプロイした先生**を返すので、
**本人確認には使いません**（使った瞬間に学級全員が先生になります）。
`ownerEmail` を書けるのは、スプレッドシートのメニュー（＝そのファイルの編集者しか出せない）と、
`active !== effective` が観測できたとき（＝「自分として実行」が確定したとき）だけです。

### B. 共通デプロイ（2 デプロイ構成・前の配り方）

```
教員: 共通URL(/class.html) → シェルでGoogleサインイン → iframe=デプロイT(?portal=1)
      → クラス作成 → 教員所有シート生成 + アプリアカウントを自動で編集者に
      → 管理画面に児童用URL( https://…/?c=K7M2QXW9 ) と QRコード表示

児童: 児童用URL(/?c=コード → /class.html?c=コード へ転送) → シェルでGoogleサインイン(IDトークン取得)
      → iframe=デプロイS（★パラメータなしの素の exec URL）
      → シェルが postMessage で「IDトークン + クラスコード」を渡す
      → GASがトークン検証+名簿照合 → 児童画面（そのクラスのシートに読み書き）
```

> ⚠️ **児童用 iframe は「素の exec URL」で開きます。** クラスコードは URL ではなく
> `app:idToken` メッセージで渡します（`?mode=student&c=…` 付き exec URL の iframe 読み込みを
> Google 側が拒否する環境が実際に確認されたため）。素 URL で 12 秒応答が無く、かつ
> アプリの起動ビーコン（`app:loaded`）も届いていない場合に限り、**旧方式（パラメータ付き URL）を 1 度だけ再試行**します。

### 3 層構成（B のみ）

1. **配布層: GitHub Pages（`docs/class.html`・PWA シェル）** … 共通 URL。Google サインイン（GIS）を担当し、ID トークンを iframe 内の GAS へ postMessage で渡す
2. **アプリ層: GAS スタンドアロンプロジェクト 1 本 + 2 デプロイ（T / S）**
3. **データ層: クラスごとのスプレッドシート（教員所有）+ 中央レジストリ（ScriptProperties）**

### 同一プロジェクトから発行する 2 つのデプロイ

| | デプロイ T（教員ポータル） | デプロイ S（児童用アプリ） |
|---|---|---|
| 実行するユーザー | **ウェブアプリケーションにアクセスしているユーザー** | **自分（アプリアカウント）** |
| アクセスできるユーザー | 全員（Google アカウント）※または同一ドメイン | 全員（＝匿名アクセス可） |
| 誰が使う | 教員のみ | 児童（教員のプレビューも可） |
| 権限の意味 | クラス作成が**教員本人の権限**で走る → シートは**最初から教員所有**。同じ実行内で `addEditor(アプリアカウント)` を呼び共有まで自動化 | すべての読み書きが**アプリアカウントの権限**で走る。**児童自身はシートへの権限ゼロ**（URL を知っても開けない） |
| 本人確認 | `Session.getActiveUser()` | **ID トークン検証**（`Auth.gs`。aud / iss / exp / email_verified を検証） |

この構成により:

- ✅ **教員がスプレッドシートを所有**（データ主権は教員側。アプリアカウントは「編集者」でしかない）
- ✅ **児童はシートへの権限を一切持たない**（UI の絞り込みではなく権限境界で防御）
- ✅ **利用者は何の設定もしない**（共有設定・ID コピペ・複製作業をすべて自動化。児童側は同意画面すら出ない — 実行者がアプリアカウントのため）
- ✅ **入り口は共通 URL 1 つ**（教員 = そのまま開く / 児童 = `?c=クラスコード` 付き）
- ✅ **完全無料**（GAS のみ）

## 🚀 A. コンテナバインドで入れる（いまの配り方・先生おひとりで完結）

準備するものは Google アカウント 1 つだけです。運営者の設定はありません。

### A-1. スプレッドシートをコピーする

配布用スプレッドシートのコピーリンクを開き、「コピーを作成」を選びます。

> **コピーリンクはまだ用意できていません。** テンプレートの作り方は
> [`docs/copy-distribution.md`](docs/copy-distribution.md) にあります。
> 用意ができるまでは、下の「A-1′. 貼り付けで入れる」でお願いします。

#### A-1′. 貼り付けで入れる（コピーが禁止されている学校向け）

1. 新しいスプレッドシートを作り、「拡張機能 ＞ Apps Script」を開く
2. 既定の `コード.gs` に `Main.gs` を貼り、「＋ ＞ スクリプト」で
   **`Db.gs` / `Schema.gs` / `Tenant.gs` / `Bound.gs` / `Gemini.gs`** を足して貼る
   （`Auth.gs` / `Registry.gs` / `TeacherApi.gs` / `StudentApi.gs` は B 専用なので要りません）
3. 「＋ ＞ HTML」で `App` を作り、`App.html` を貼る
4. 「プロジェクトの設定」で `appsscript.json` をエディタに出し、
   本リポジトリの **`appsscript.bound.json`** の中身にする

### A-2. 「はじめの設定」を 1 回押す

スプレッドシートに戻ると、上のメニューに **「みっけ！」** が出ます
（出ないときは再読み込みしてください）。
**「はじめの設定（先生として登録）」** を押すと、

- 必要なシート（`Members` / `Settings` / `Units_単元` / `Pins_ピン` …）が作られ
- **押した方が、この学級の先生として `Settings` シートに記録され**
- シートの作りの点検結果が出ます

> **押した人が先生になります。** メニューはそのファイルの編集権を持つ人にしか出ないので、
> 児童が先生になることはありません。児童にこのスプレッドシートを共有しないでください。

### A-3. ウェブアプリとして公開する

「拡張機能 ＞ Apps Script ＞ デプロイ ＞ 新しいデプロイ ＞ ウェブアプリ」で、

| 項目 | 値 |
|---|---|
| 次のユーザーとして実行 | **自分** |
| アクセスできるユーザー | **同一ドメインの全員** |

- 「自分」にすると読み書きが先生の権限で走るので、**児童はスプレッドシートへのアクセス権を 1 つも持たなくて済みます**。
- 「アクセスできるユーザー」を **「全員」にしないでください。** `Session.getActiveUser().getEmail()` が
  空になり、**先生ご自身も含めて誰も入れなくなります**（画面にその旨が出ます）。
- **やり直すときは「デプロイを管理 ＞ 既存のデプロイを編集」**。「新しいデプロイ」を作ると
  `/exec` の URL が変わり、配ったリンクが全部切れます。

出てきた `/exec` の URL を学級に配れば準備完了です。

### A-4. シートを触ってしまったとき

列は**見出しの名前**で読み書きしているので、列を足したり並べ替えたりしても動きます。
困るのは見出しの行ごと消えたときで、そのときは
メニュー「みっけ！ ＞ シートを点検する」（または教師用コンソールの「学級の管理 ＞ シートの点検」）が
どこがどうなっているかを出します。
**「シートを直す（足すだけ）」は足りないシートと列を足すだけ**で、消したり動かしたりはしません。

## 🚀 B. 共通デプロイで入れる（前の配り方・運営者の初回セットアップ）

> セットアップするのは**運営者（アプリアカウントの持ち主）だけ**です。先生・児童は何も設定しません。
> **すでにこの形で公開している学級のために残しています。** これから入れるなら A をおすすめします。

### Step 0: アプリアカウントを用意

- アプリ運営用の Google アカウント（例: `mikke-app@gmail.com`）を用意し、**2 段階認証を必ず有効化**。パスワードは共有しないでください。

### Step 1: GAS プロジェクト作成

1. **アプリアカウントで** [script.google.com](https://script.google.com) から**スタンドアロン**プロジェクトを作成（スプレッドシートには紐付けない）
2. 本リポジトリの `*.gs` と `App.html` を同名ファイルとして貼り付け（[clasp](https://github.com/google/clasp) 推奨: `clasp push` で一括反映）
3. プロジェクトの設定で「appsscript.json をエディタで表示」を有効にし、本リポジトリの `appsscript.json` の内容にする

### Step 2: OAuth クライアント ID（GIS 用）を作成

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作成 → 「API とサービス > 認証情報」
2. OAuth 同意画面を構成（外部 / アプリ名「みっけ！」）
3. 「認証情報を作成 > OAuth クライアント ID > **ウェブアプリケーション**」
   - 承認済みの JavaScript 生成元: あなたの GitHub Pages のオリジン（例: `https://<user>.github.io`）
4. 発行されたクライアント ID を控える

### Step 3: ScriptProperties（配布元設定）

GAS エディタ「プロジェクトの設定 > スクリプト プロパティ」に以下を登録:

| キー | 必須 | 値 |
|---|:--:|---|
| `sp_appAccountEmail` | ✅ | アプリアカウントのメールアドレス |
| `sp_googleClientId` | ✅ | Step 2 のクライアント ID（ID トークンの `aud` 検証に使う） |
| `sp_shellUrl` | ✅ | GitHub Pages の URL（例: `https://<user>.github.io/Townmap_Mikke/`）。児童用 URL / QR の生成に使う |
| `sp_dbTemplateId` | – | （任意）DB テンプレートのスプレッドシート ID。指定するとクラス作成時にこれを複製する |

⚠️ ScriptProperties にはこれらの `sp_*` とレジストリ（`cls_*` / `own_*`）以外を置かないでください（1 値 9KB / 全体 500KB 程度の制限があるため。個人設定・クラスデータは各クラスのシート側に保存されます）。

### Step 4: 2 本のデプロイを発行

「デプロイ > 新しいデプロイ > ウェブアプリ」を **2 回** 行います。

| | デプロイ T（教員ポータル） | デプロイ S（児童用） |
|---|---|---|
| 説明 | `teacher-portal` | `student-app` |
| 次のユーザーとして実行 | **ウェブアプリケーションにアクセスしているユーザー** | **自分（アプリアカウント）** |
| アクセスできるユーザー | 全員（学校運用なら「同一ドメイン」も可） | 全員 |

- `appsscript.json` の `webapp` 設定（`USER_ACCESSING` / `ANYONE`）は **T 用の値**です。デプロイ画面で個別に上書きされるため、**実際の実行モードは各デプロイの設定が正**です。上の表どおりに設定してください。
- デプロイ S は初回に一度「アクセスを承認」が必要です（アプリアカウントとして承認）。

### Step 5: GitHub Pages（シェル）

1. このリポジトリの `docs/config.js` に T / S の exec URL とクライアント ID を記入して push
2. リポジトリ設定 > Pages で `docs/` を公開
3. 公開 URL が `sp_shellUrl` と一致していることを確認（**オリジンが 1 文字でも違うと、シェルからのメッセージがすべて無視されます**）

これで完了です。**先生に共通 URL を伝えるだけ**で運用が始まります。

### Step 6（推奨）: 設定が正しいか自己診断する

`https://<シェルURL>/diag.html` を開くと、config.js・Service Worker のキャッシュ状態・デプロイ S のサーバー設定（匿名アクセス可か / 実行者がアプリアカウントか / `sp_*` が揃っているか / `sp_shellUrl` のオリジン一致）・CDN の到達性・iframe の読み込み可否を自動判定します。

2. 「クラスを作成」→ **自分のドライブ**に記録用スプレッドシートが自動作成される

5. アプリを開き、管理パネルの「単元・設定」で**地図の画像を登録して単元を開始**する

初回同意画面に出るスコープは次の 3 つだけです（`DriveApp` を使わない設計でフル Drive スコープを回避しています）:
`spreadsheets`（シート操作・共有追加）/ `script.external_request`（トークン検証・Gemini）/ `userinfo.email`（本人特定）

> 📖 画面ごとの詳しい手順は [MANUAL.md](MANUAL.md) を参照してください。

## 🧒 児童の使い方（設定ゼロ・同意画面なし）

1. 先生からもらった URL / QR を開く → Google でサインイン
2. 表示名（ニックネーム可）を入れて「参加する」→ 先生の承認後に自動で入室
3. 以降はふつうにピン・チャットが使えます。**スプレッドシートの URL を知っていても児童は開けません**（権限がないため）

## 🚑 トラブルシューティング: 児童の入り口がブロックされる・つながらないとき

児童の入り口は「① シェルでの Google サインイン → ② iframe でのデプロイ S 読み込み → ③ アプリ起動（CDN + ハンドシェイク）」の 3 関門を通ります。**どこで止まったかで原因が異なる**ため、まず `https://<シェルURL>/diag.html?c=<クラスコード>` （接続診断ページ）を児童の端末で開き、結果をコピーしてください。デプロイ S には `?diag=1` を付けて fetch すると設定を自己申告する診断 API があり、diag.html が自動判定します。

### ① サインインの時点で「アクセスがブロックされました」と出る（Google の画面）

コードでは直せません。**OAuth / 管理コンソール側の設定**が原因です。

| 画面の文言 | 原因 | 対処 |
|---|---|---|
| 「このアプリは Google の審査プロセスを完了していません」(access_denied) | OAuth 同意画面が**テスト**公開のまま。テストユーザー以外は全員拒否される | Cloud Console > OAuth 同意画面 > 「**本番環境に移行**」 |
| 「このアプリは確認されていません」（警告画面・続行は可能） | アプリ未検証。機密スコープを使っていないため続行はできるが、**未検証のままだと利用者数上限（100 人）**に達した時点で新規ユーザーがブロックされる | 検証を申請するか、利用規模を確認 |
| 「管理者によってブロックされています」「組織でこのアプリは許可されていません」 | **Google Workspace for Education では 18 歳未満のアカウントはサードパーティ製アプリへのアクセスが既定でブロック**される（2023 年以降の Google の仕様） | 学校の管理コンソールで 「セキュリティ > API の制御 > **アプリのアクセス制御**」 から本アプリの**クライアント ID を「信頼済み」として許可**してもらう。利用校ごとに必要 |

> 💡 マルチテナントで「どの学校でも設定ゼロ」を目指す場合でも、**児童アカウントが Education テナント管理下にある限り、この管理者許可だけは各校で必要**です。回避したい場合は「児童は Google サインインを使わない参加方式（先生が発行するクラス内 PIN など）」への設計変更が必要になります。

### ② iframe が真っ白 / 「ファイルを開くことができません」/ ログイン画面が見える

- **最重要: デプロイ S の「アクセスできるユーザー」は「全員」（＝ Google アカウント不要の匿名アクセス、API 上の `ANYONE_ANONYMOUS`）でなければなりません。**「Google アカウントを持つ全員」（`ANYONE`）だとログインが必須になり、児童モードは Cookie を送らない（`credentialless` iframe）ため **accounts.google.com へのリダイレクト → ログイン画面は iframe 表示不可 → 必ずブロック**されます。
  - 確認方法: **シークレットウィンドウ**で S の exec URL を直接開く。ログイン画面が出たら設定ミスです。
  - ⚠️ `appsscript.json` の `webapp` は T 用の値（`USER_ACCESSING` / `ANYONE`）です。**clasp や API からデプロイを作成すると S もこの値で作られてしまう**ため、S は必ずデプロイ画面（UI）で「自分として実行 / 全員」に設定してください。
- **コード更新がデプロイに反映されていない**: GAS はコードを保存しても既存デプロイは古いバージョンのまま動き続けます。「デプロイ > デプロイを管理 > ✏️ > バージョン: **新バージョン**」で T / S **両方**を更新してください（exec URL を変えないため「新しいデプロイ」ではなく既存の編集で）。
- 学校のフィルタが `script.google.com` / `*.googleusercontent.com` を遮断しているケースもあります（診断ページで判定可）。

### ②′ アプリの画面は出るが「UrlFetchApp.fetch を呼び出す権限がありません」等の権限エラーが出る

デプロイ S は「自分（アプリアカウント）として実行」のため、実行時の権限は**アプリアカウントが事前にこのスクリプトへ与えた承認**で決まります。`appsscript.json` の `oauthScopes` を変更（追加）した場合や、初回の「アクセスを承認」を飛ばした場合、保存済みの承認に必要なスコープが含まれず、児童の操作（ID トークン検証 = UrlFetch）が権限エラーになります。

**対処（1 分で完了・再デプロイ不要）:**

1. **アプリアカウントで** GAS エディタを開く
2. プロジェクトの設定で「appsscript.json をエディタで表示」が有効で、`oauthScopes` に 3 つ（`spreadsheets` / `script.external_request` / `userinfo.email`）が並んでいることを確認
3. エディタ上部の関数選択で **`authorizeApp`**（`Main.gs`）を選び「実行」
4. 「承認が必要です」→ アプリアカウントを選択 →（「このアプリは確認されていません」と出たら「詳細」→「（安全ではないページに）移動」）→ **すべて許可**
5. 実行ログに「UrlFetch(トークン検証): OK」と出れば完了。児童用 URL を再読み込み

> 💡 デプロイ T（教員側）も同様で、スコープ変更後は各教員に初回アクセス時の再承認画面が一度出ます（これは正常な動作です）。

### ③ ページは届くがアプリが起動しない（「うまくつながらないみたい」）

- アプリ本体は `unpkg.com`（React / Babel）と `cdn.tailwindcss.com` に依存しています。**学校のフィルタでこれらの CDN が遮断されていると起動できません**。診断ページの「アプリ部品」の結果を確認し、ネットワーク管理者に許可を依頼してください。
- `sp_shellUrl` のオリジンが実際の GitHub Pages のオリジンと一致していないと、アプリはシェルからのメッセージを**すべて無視**します（トークンが届かず接続待ちのまま）。診断 API が不一致を検出します。
- 古いシェルが Service Worker キャッシュに残っている場合は、診断ページの「キャッシュを全部消して再読み込み」を実行してください。

## 🔐 セキュリティ設計（信頼境界）

- **信用できる入力は 2 つだけ**: デプロイ T では `Session.getActiveUser()`、デプロイ S では**検証済み ID トークン**。`e.parameter`・postMessage・`google.script.run` の引数はすべて改ざん可能として扱う
- すべての API はサーバー側で「①トークン検証 → ②クラス解決 → ③名簿照合(status=active) → ④役割チェック → ⑤行所有者チェック」の 5 段ガードを通す。フロントの出し分けは防御とみなさない
- **クラスコードは宛先であって認証ではない**: 8 桁（紛らわしい `I/1/O/0` を除いた 32 文字から生成、約 1.1 兆通り）。コードが漏れても名簿にない者は `unregistered` 止まり。参加承認制が既定で ON。コード再発行・受付停止も管理画面から可能
- **スプレッドシート ID / 他児童のメールアドレスは児童側に一切露出しない**（児童向けレスポンスでは email を `sha256(email)` 先頭 12 桁の匿名 ID に置換）
- 書き込み者の email は常にサーバー側で決定する（フロントから渡された email は使わない）
- GAS は frame-ancestors の特定オリジン限定ができないため `ALLOWALL` を使うが、その代償として ID トークン検証とシェル側の origin 検証（`script.google.com` / `*.googleusercontent.com` のみ受理）を必須の防御線とする
- 画像は Drive を使わず、圧縮した Data URL をクラスシート内 `Images_画像` に**40,000 文字ずつ分割して**保存（Drive 権限も共有リンクも発生しない）
- ID トークンは `sessionStorage` にのみ保持（`localStorage` には置かない）

## 📲 PWA（配布シェル・B のみ）

`docs/class.html` が GitHub Pages 上の PWA シェルです（`docs/index.html` は導入の案内ページ）。
A（コンテナバインド）では、児童は先生の `/exec` を直接開くのでシェルを通りません。

- **ホーム画面に追加できる**: `beforeinstallprompt` を `<head>` 最上部の `pwa-install-hook.js` で捕捉し、ログイン画面に「📲 アプリを入れる」ボタンを出す（iOS は手動追加。手順は [MANUAL.md](MANUAL.md)）
- **他アプリを壊さない**: Service Worker は `mikke-shell-` で始まる**自アプリのキャッシュだけ**を削除する。旧配信元の `gigayama.github.io` は多数のアプリが同一オリジンを共有しているため、これは必須の制約
- **勝手に切り替わらない**: `skipWaiting()` は自動では呼ばず、「あたらしい バージョンが あります → さいしんに する」を押した時だけ更新する
- **GAS と GIS はキャッシュしない**: `script.google.com` / `*.googleusercontent.com` / `accounts.google.com` はクロスオリジンとして素通し。`diag.html` も常にネットワークから取得
- **オフライン**: 画面遷移は network-first。圏外ではキャッシュ済みシェル → `offline.html` の順にフォールバック

### リリース手順（シェルを更新するとき）

1. `docs/` の中身を直したら **`npm run build:sw`** を実行する。
   `docs/sw.js` の `APP_VERSION` は**配信物の中身から自動で採番**されます（手で直さないこと）。
2. `npm run check` が通ることを確かめて push → GitHub Pages に反映
   → 端末側では「さいしんに する」で切り替わる

- **版を上げ忘れると、古いシェルのキャッシュが掃除されず、直した画面が児童の端末に一度も届きません。**
  CI の `npm run check` が `build:sw --check` を含んでいるので、上げ忘れは赤くなります。
- `docs/diag.html` の「シェルのキャッシュ状態」は、**配信中の `sw.js` を読んで**現在の版を知ります。
  合わせる定数はもうありません（以前は手書きの `CURRENT_CACHE = 'mikke-shell-v6'` で、
  自動採番に変わったあと**どんなに古いキャッシュでも「異常なし」**になっていました）。

`.gs` / `App.html` を更新した場合:

- **A（コンテナバインド）** … 先生ごとに別のプロジェクトなので、こちらからは届きません。
  直しを届けたいときは、先生に貼り直し（またはテンプレートの作り直し）をお願いします。
- **B（共通デプロイ）** … main への push で `deploy.yml` が `clasp push` と既存デプロイの
  差し替えまで行います。手で「新しいデプロイ」を作らないこと（`/exec` の URL が変わり、
  配ったリンクが全部切れます）。`--deploymentId` は T / S の 2 本ぶん必要です。

## ⚙️ 運用上の注意

- **アプリアカウント**: 2 段階認証必須・パスワード非共有。このアカウントが侵害されると全クラスのシートに書き込める点に注意
- **教員がアプリアカウントの編集権限を外すと、そのクラスは機能停止**します。児童画面のエラーメッセージに復旧手順（共有し直し）が案内されます
- **クォータ**: デプロイ S は全児童がアプリアカウントの割り当てを消費します
  - 同時実行 約 30 / UrlFetch 日次 20,000 回（無料アカウント。Workspace は 100,000 回）。ID トークン検証はキャッシュ前置（TTL 300 秒）で 40 人クラスでも余裕があります
  - 書き込みは ScriptLock で直列化（保持区間は appendRow 1 回程度に最小化）。競合時はフロントが指数バックオフで自動リトライ
  - 時間主導トリガーを追加する場合は**クラス数×トリガーにせず**、1 本のトリガーでレジストリを走査する設計にすること
- **水平分割の拡張余地**: 利用校が増えたら「学校ごとに S を別アプリアカウントでデプロイし、レジストリに exec URL を持たせて振り分ける」構成に拡張できます（コード変更は Registry のレコードに `execUrlS` を足し、シェルが `?c=` 解決時に向き先を選ぶだけ）
- **データ主権**: 児童データは教員所有シートにあり、アプリアカウントは編集権限のみ。クラス廃止時もシートは教員の手元に残ります
- **Gemini API キー**: クラスごとにそのクラスのシート（`Settings`）に保存されます。クラスをまたいで共有されません

## 🔄 旧バージョンからの移行

- **旧バインド型デプロイはそのまま動き続けます**（`getSs_()` が `getActiveSpreadsheet()` を優先。名簿も旧 `Users_名簿` を使用）
- 旧 DB を新構成に移行する場合は、教員ポータルの「既存のスプレッドシートをクラスとして登録」を使ってください。不足シートが補完され、`Users_名簿` は `Members` に自動移行されます（`Members` が空の場合のみ）
- 旧版の `getDriveImages`（ドライブ画像ピッカー）は、フル Drive スコープ回避のため**アップロード方式に置き換え**られました

- `Schema.gs` を新設。スプレッドシートのメニューから、シートの作りの点検と
  **足すだけの修整**ができる。消す・動かす・見出しの行ごと消えているときに書き戻す、はしない
- **シートの読み書きを列の位置から見出しの名前に変えた**（`Db.gs`）。
  先生が列を 1 本挿しただけで、メモの中身が「なまえ」の列に入り、`is_active` に日付が入り、
  名簿照合が全員 NOT_MEMBER になっていた。しかも画面には何も出なかった
- **児童が書いた文字をセルに入れる前に無害化**（`safeCellText_`）。

- `npm run check`（SW の版・構文・App.html の JSX・テスト）を新設。

### 2026-07 — 学習画面の強化

**学習画面（地図）の最大化**

- 地図画像が端末の画面サイズを実測して**余白最小で最大表示**されるようになりました（従来は 85vw × 75vh 固定）。スマートフォン・タブレット・PC のどの端末でも、回転やリサイズに自動追従します
- **2 本指ピンチズーム**（タブレット・スマホ）と**マウスホイール / トラックパッドズーム**（PC）に対応。いずれも指やカーソルの位置を支点に拡大縮小します（最大 6 倍）

**気づきの入力・整理・再入力**

- **ピンの編集機能**を追加。自分のピンは詳細画面の「✏️ なおす」からタイトル・メモ・アイコン・写真をいつでも書き直せます（他人のピンは編集不可。サーバー側でも行所有者チェックを強制）
- **「📒 わたしのきろく」パネル**を新設。自分の気づきを新しい順に一覧・キーワード検索でき、その場で「なおす」「地図で見る」ができます
- 編集モード中でもピンをタップして詳細を見られるようになりました（モード切替の手間を削減）

**修正した主なバグ**

- ズームボタン等の UI をタップするとピン作成モーダルが誤って開くことがある問題
- 日本語入力（IME）の変換確定 Enter でチャット・コメントが途中送信される問題
- `animate-pop-in`（fill-mode: forwards）が `-translate-x-1/2` を上書きし、地図タブ・トースト・作成中ピン・ローディング表示が**中央からズレて表示**される問題
- 先生が新しい単元を開始しても、児童の画面が再読み込みするまで**永久に切り替わらない**問題（SyncData が現在アクティブな単元を返すよう修正）
- 最初の単元を作成した直後、再読み込みしないと地図が表示されない問題
- 定期同期が、直前の楽観的更新（さしたばかりのピン等）を一時的に巻き戻すことがある競合
- 地図追加後に表示中の地図タブが先頭に戻ってしまう問題
- 非表示タブでも定期同期が走り続け、サーバーのクォータを消費する問題
