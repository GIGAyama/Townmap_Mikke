## 貼るまえに直すところ

1. **連載番号**。本文 1 行目の `#◯` を実際の番号に置きかえてください。過去記事を取りにいけない環境で書いたため、推測で埋めていません。
2. **タイトル**。1 行目のうち `#◯` から後ろがタイトル本体です。長ければ「町たんけんの気づきが1枚の地図に集まるアプリ「みっけ！」」だけでも成立します。
3. **公開 URL**。「はじめに」に `https://gigayama.github.io/Townmap_Mikke/` を載せています。GitHub Pages の公開設定と `sp_shellUrl` が現在この URL であることを確認してから公開してください。ここが違っていると、記事から入った先生が入り口にたどりつけません。
4. **アプリを用意する側の手順**を README に案内しています。もし note 側に別の導入記事があるなら、そちらへのリンクに差しかえたほうが親切です。

## note への貼りかた

1. note の新規記事で、1 行目のタイトルを本文からコピーして貼る（`# ` は外す）。
2. 本文は 2 行目以降をそのまま貼り付ける。見出しは `##` が大見出し、`###` が中見出しとして反映される。note は大見出しから目次を自動で作る。
3. 画像は自動では入らない。`images/` の中を、本文に出てくる順（ファイル名の番号順ではなく、本文の `![...]` の順）に手でアップロードして、対応する段落の位置に置く。
4. 画像の下の 1 行はキャプションなので、note のキャプション欄に移す。本文からは消す。
5. ハッシュタグ欄には `#GIGAスクール` `#小学校` `#教育ICT` `#生活科` `#社会科` `#町探検` `#GoogleAppsScript` あたり。

## 撮り直すときの手順

撮影用の道具は `.tmp-shots/` に置いてありましたが、納品時に消しました。もう一度撮る場合は次の考えかたで組み直せます。

このアプリは Google Apps Script 上でしか動かないため、そのままではブラウザの自動操作にかけられません。そこで、本番の `.gs`（Main / Registry / Auth / Db / Tenant / StudentApi / TeacherApi）をブラウザにそのまま読みこませ、`SpreadsheetApp` などのサービスだけをメモリ上の代役に差しかえて動かしました。`App.html` は一切書きかえていないので（CDN の参照先と、`doGet` が埋める起動情報の 2 か所を除く）、写っている画面は本番と同じものです。

手順は次のとおりです。

1. `npm i --no-save playwright react@18 react-dom@18 @babel/standalone tailwindcss@3`
2. `App.html` の CDN 参照（unpkg の React と Babel、cdn.tailwindcss.com、Google Fonts）を、手もとに置いた同じものに差しかえる。Tailwind は `cdn.tailwindcss.com` と同じ設定で CLI からビルドする
3. `<?= bootMode ?>` などの埋めこみを外し、代わりに URL のパラメータから起動情報を作る
4. `google.script.run` を、読みこんだ `.gs` の関数を呼ぶだけの偽物に差しかえる
5. サンプルのクラスは、シートに直接書きこまず `tpCreateClass` `stSubmit` などの本番の API を呼んで作る。こうすると、データの形が本番とずれない
6. 静的サーバで配り、`capture.mjs` のシナリオで操作して撮る

つまずきやすいところが 3 つありました。

- CDN が学校のフィルタと同じく外に出られない環境だったので、React も Babel も Tailwind も書体も、npm と Google Fonts から取って手もとに置いた。書体を落とすと丸ゴシックが出ず、本番と印象が変わってしまう
- クラスコードは作るたびに変わるので、URL を書けない。発行されたレコードを固定のコードに移して撮った
- ピンの位置は、地図の画像の実測サイズから割合で計算しないと、ビューポートが変わるたびにずれる

## 撮影中に踏んだ範囲と、見つかった不具合

見つかった不具合はありません。ただし「どこまで踏んだか」を書いておきます。

実際に操作して画面が出ることを確認したのは次のところです。教員ポータルの初回表示、クラス作成、クラス管理画面（URL と QR の生成、受付と承認制のスイッチ）、参加申請の承認待ち表示、名簿の一括登録、単元の作成、2 枚目の地図の追加、児童の参加申請と承認待ち、児童の地図表示、ピンの作成（写真つきを含む）、ピンの詳細、コメント、いいね、なげなわ選択、班でのしぼりこみ、地図タブの切りかえ、拡大と戻す、わたしのきろく、みんなのひろば、管理パネルの 4 つのタブ、学習分析での児童の選択。落ちた画面はありませんでした。

**踏んでいないところ**もあります。記事では触れていない機能ですが、公開前に本番で一度さわっておくと安心です。

- ピンとチャットの削除、クラスコードの再発行、クラスの廃止、既存シートのクラス化
- AI ポートフォリオの生成（Gemini への通信が必要なため、撮影環境では動かしていません）
- 印刷（ブラウザの印刷ダイアログを開く動作のため）
- PWA としてのインストールと、オフライン時の案内画面

また、撮影は「本番の `.gs` をブラウザで動かし、スプレッドシート部分だけをメモリ上の代役に差しかえた」環境で行っています。画面を作るコードとサーバー側の処理は本番と同じものが動いていますが、Apps Script 固有のふるまい（実行時間の上限、同時書き込みのロック、クォータ）はこの方法では再現できません。そこに起因する不具合が無いことまでは確認できていません。
