# マニュアル用の画面写真の撮り方

土台は **note-article スキルの `scripts/capture.mjs` をそのまま使う**。
落とし穴（ふりがなを落とした文字照合、押せたことの確かめ方、同じ絵の警告など）は
`note-article/references/screenshots.md` に全部書いてあるので、先に読む。

ここに書くのは、**紹介記事用の撮り方と、マニュアル用の撮り方の違い**だけ。

## 記事の絵とマニュアルの絵は、目的が違う

| | 紹介記事 | マニュアル |
| --- | --- | --- |
| 見せたいもの | 教室の場面。「こんなふうに使える」 | いま押すもの。「これを押す」 |
| 画面の入れ方 | 中身が入って賑やかなほうがいい | 中身は少なめ。押すものが埋もれない |
| 枚数 | 節に 1〜2 枚 | **機能に 1 枚。全部** |
| 撮る範囲 | 画面まるごと | **押すものの周り**に寄せてよい |
| 名前 | 話の順 | **本文の手順の順**（01- からの連番） |

## 1. 1 機能 1 枚。書いたのに撮っていない機能を作らない

「できること」の `###` の数と、画像の枚数が合っているのがふつうの状態。
合わないときは、どちらかが漏れている。

撮影のシナリオは、機能の一覧をそのまま並べた形にする。
そうすると、機能を数え忘れたときにシナリオの側でも気づける。

## 2. 押すものが画面の中で分かるように撮る

全画面で撮ると、押してほしいボタンが 1920px の中の 40px になる。
読み手は探せない。次のどちらかにする。

- そのボタンを含む区画まで `resize()` で狭めてから撮る
- 画面を広いまま撮るなら、本文の側で「左上の」「画面のいちばん下の」と
  場所を言葉で足す

⚠️ **矢印や丸を画像に描き足さない。** 画面が変わったときに、絵だけが古くなって
残る。しかも古いことに誰も気づけない。場所は言葉で指す。言葉なら、
画面と食い違ったときに本文の側で直せる。

## 3. 実物の中身を入れない（Zero PII）

マニュアルの写真は、記事より長く残る。子どもの名前・出席番号・学級名・
学校名が写った画面を、1 枚でも撮らない。

入れる中身は、その場で作った当たり障りのないものにする。
「たろう」「はなこ」のような、教科書に出てくる名前を使う。

## 4. 動きの途中を撮らない

`capture.mjs` の `shot()` は画面が止まるまで待つが、待ちきれないこともある。
アニメーションのあるアプリでは `freeze()` を呼んでから撮る。

途中の絵は「押したのにこうならない」という問い合わせを生む。

## 5. 名前は本文の手順の順

`01-home.png` `02-setup-grade.png` のように、2 桁の連番＋短い英語。

順番が本文とずれると、直すときに全部を突き合わせることになる。
**本文を書いてから撮る**か、**撮ってから本文を書く**か、どちらかに決めて、
途中で入れ替えない。

## 6. 撮り終わったら、出力の最後を読む

`capture.mjs` は画面のエラーと「同じ絵が続いた」警告をまとめて出す。
`--strict` を付けると、警告があれば異常終了する。**付けて撮る。**

撮れているつもりで同じ画面が 20 枚並ぶ、というのがいちばん多い失敗で、
しかも本文を書き終わるまで気づけない。
