# 更新ログを書く

アプリを直したあと、**使う人から見て何が変わったか**を 1 行足す。

納品物は 1 本だけ。

```
docs/CHANGELOG.md
```

## なぜ機械で作らないのか

はじめはコミットの題（`feat:` / `fix:` …）から自動で作るつもりだった。
**実際に数えてやめた**（2026-08-24 に 3 本を調べた結果）。

| リポジトリ | 直近のコミット |
| --- | --- |
| Typa | 10 件すべてが `chore(gate)` / `chore(drift)` / `chore(sw)` |
| カベカベ合戦 | 12 件のうち 9 件が同じ。残る 3 件も scope が `gate` / `build` |
| デジタル新聞社 | ここだけ `feat` が並ぶ（作り直した直後だった） |

正本を配る仕組みが、同じコミットを 42 本のリポジトリに撒く。機械的に出すと、
紹介ページに「秘密の直書きの検査を入れる」と並ぶ。**使う先生から見れば、
アプリは何も変わっていない。**

> **「何が変わったか」は、使う人から見て何が変わったかであって、
> リポジトリで何をしたかではない。それを分けられるのは書いた本人だけ。**

だからここは手で書く。書式と、書くもの・書かないものは
`references/format.md` にある。**書く前に必ず読むこと。**

## 書き方（最短）

```md
## 2026-08-23
- 写真の上限をなくしました
- 音が出ない端末があったのを直しました

## 2026-06-01
- はじめて公開しました
```

- 日付の見出しは `## YYYY-MM-DD`。**この形でないと機械が拾わない**（書いたのに出ない）
- 項目は `- ` で始める
- 新しい日付を上に足す
- 1 項目 1 変更。「〜しました」で言い切る

## どこに出るか

| 出る先 | 何件 |
| --- | --- |
| `giga-school.com`（トップの「更新したこと」） | 全アプリ横断。新しい 4 日付・全体 12 項目・1 アプリ 1 日 3 項目まで |
| `/apps/<slug>/`（紹介ページ） | 直近 3 日付 |
| `/apps/<slug>/manual/`（使い方マニュアル） | 直近 3 日付 |

**書いていないアプリには何も出ない。** 全部のアプリで書く必要はなく、
よく使われているものだけで意味がある。消した行はその朝に消える。

⚠️ 上限で切られたものは**黙って落ちる**。切った先に一覧ページが無いので
「ほか N 件」も出ない。大事なものを先に書く。

## 出す前に

```bash
node .claude/skills/giga-changelog/scripts/lint-changelog.mjs docs/CHANGELOG.md
```

落ちるのは**機械が拾えなくなるものだけ**（`## 2026/08/23` のような書式ちがい、
中身の無い日付）。言い回しは `warn` で言うだけで止めない ——
検査で好みを強制すると、書き手がこの検査を通さなくなる。

## いつ書くか

**直したその場で 1 行足す。** あとでまとめて書こうとすると、
コミットの題を見ながら書くことになり、使う人から見た言葉に翻訳できなくなる。
